WHAT IS EVE-OS?

Stop managing snowflake edge nodes.
Start orchestrating a fleet.

Traditional edge = agents on top of Ubuntu + manual SSH + bricked updates. EVE-OS replaces the whole stack with a type-1 hypervisor OS that runs everything as Edge Containers — no logins, no passwords, 100% API-driven.

◈

Zero-Touch

Install once. Never need physical access again. All hardware, network and app lifecycle is managed remotely via controller API — even over flaky links.

⬢

Zero-Trust

No SSH, no usernames, no passwords. TPM-based device identity, measured boot, remote attestation, signed updates and full-disk encryption by default.

⬣

Cloud-Native for Edge

Brings DevOps to the field: declarative config, GitOps workflows, atomic OTA updates with rollback, distributed firewall and automated connectivity.

KEY CAPABILITIES

Built for the harsh reality of the field

🔐 Hardware root of trust

TPM 2.0 crypto ID, measured boot, remote attestation, signed updates, encryption at rest.

📦 Any workload

Docker/OCI containers, Kubernetes clusters, VMs with any guest OS, and unikernels — side by side.

🖥️ Any hardware

x86, Arm, RISC-V, GPU. Bare metal or VM. Assign CPU cores, GPUs and I/O ports per app.

🔄 Unbrickable updates

Dual-partition atomic A/B updates with automatic rollback. Patch without truck rolls.

🌐 Resilient networking

Distributed firewall, VPN overlays, multi-uplink, offline operation. Policy-based routing per app.

🎛️ Open EVE API

Declarative protobuf config from controller. Works with open-source Adam or commercial controllers (e.g. ZEDEDA).

🧊 I/O isolation

Block unused USB/serial ports to prevent tampering. Pass through devices securely to specific apps.

📡 Disconnected ops

Nodes keep running without controller. Local cached policy enforces last-known-good state.

ARCHITECTURE

Microservices on a hardened hypervisor

EVE-OS is structured as loosely-coupled microservices (inspired by Qubes OS, ChromeOS, CoreOS) on top of Xen / KVM + LinuxKit. Each domain handles security, updates, connectivity and app orchestration.

EDGE CONTAINERS

One packaging model for everything

Docker / OCI as Edge Containers

Push any OCI image to EVE via controller. EVE handles networking, volumes, restarts, logs and remote debug. Ideal for AI inference, protocol gateways, data pipelines.

eden pod deploy --name infer \
  -p 8080:8080 --memory 2GB \
  my-registry/quality-inspect:v2.4

Keep legacy investments

Run full Windows or Linux VMs alongside new containers. Pin vCPUs, pass through GPUs, USB and serial. Migrate SCADA, HMI and VNFs without rewrites.

# eve config snippet (JSON)
{ "vms": [{ "name": "scada-gw",
  "guest": "windows-10-iot", "vcpus": 2,
  "passthrough": ["pci/0000:00:14.0"] }] }

Kubernetes at the edge

Deploy k3s or full K8s as an app on EVE. Let EVE own the hardware, TPM and network while K8s owns microservices. Best of both orchestrators.

eden pod deploy --name k3s rancher/k3s:v1.29 \
  --vcpus 4 --memory 8GB --disk 20GB

GET STARTED / VIRTUAL LAB

Run EVE-OS virtually in 15 minutes

No hardware needed. Boot EVE in QEMU on your laptop and manage it with the open-source Adam controller + Eden CLI.

1

Prerequisites

Linux/macOS, 8GB RAM, Docker, QEMU, Go 1.21+. git clone https://github.com/lf-edge/eve.git

2

Build EVE live image

make live — produces live.raw / ISO. Enable TPM emulation for full attestation demo.

3

Start Adam + Eden

eden setup → eden start. Adam serves as local controller with EVE API on :443.

4

Boot EVE node

eden eve onboard then make runeve. Watch onboarding in eden eve log.

5

Deploy apps

eden pod deploy nginx, expose ports, push configs. Pull logs, exec, update OTA — all remotely.

FAQ

Quick answers

Is EVE-OS a Linux distro I can SSH into?

No. EVE-OS is a hypervisor OS — there are no user accounts or SSH. You manage nodes exclusively through a controller via the EVE API. This is what makes it zero-trust and unbrickable.

What hardware does it need?

Any x86, Arm, RISC-V or GPU machine, bare metal or VM. 2+ GB RAM recommended for trials, TPM 2.0 recommended for full security (emulated TPM works in QEMU).

Do I need a paid controller?

No. Use open-source Adam for single-node labs. For fleets (monitoring, policies, multi-tenancy at scale) use a commercial controller like ZEDEDA that speaks the same open EVE API.

How are updates safe?

Dual A/B partitions, signed images, automatic rollback on failed boot/health checks. The node always has a known-good image to fall back to.

Can it run Kubernetes?

Yes — run k3s/K8s as an Edge Container app. EVE handles hardware, security and networking; Kubernetes handles your microservices inside.

Where do I get help?

LF Edge Slack (#eve), GitHub issues/discussions, weekly TSC calls and eve-os.readthedocs.io. Contributions welcome — hardware support, docs, testing.
